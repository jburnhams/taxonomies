## What is distinctive

The most practical short guide to building a faceted classification; the procedure our design borrows.

## Notes

Seven steps (verbatim headings):
1. **Domain collection**: gather a representative sample of the things.
2. **Entity listing**: list them and break each description into basic concepts.
3. **Facet creation**: group the concepts into facets that are mutually exclusive and jointly exhaustive.
4. **Facet arrangement**: order the values inside each facet, and test-classify.
5. **Citation order**: fix a default order for combining facets.
6. **Classification**: classify the whole domain.
7. **Revision, testing, and maintenance.**
Uses Spiteri's principles as the test for a good facet, and says the values should be a controlled vocabulary. Also summarises Kwasnik (1999) on hierarchies, trees, paradigms and facets, with page references.

Checked against the stored page 2026-11-25 (the second half was a summary in the first pass):
- **When to use facets** (§1): if a hierarchy, tree, paradigm, timeline or size order works, use it; "The design of the classification must follow its purpose". Facets are for **three or more** independent dimensions.
- **Steps map to the planes**: facet creation is "the Idea Plane"; final facet arrangement works on the Idea and Verbal planes and is where to fix the controlled vocabulary (choose between "chick peas" and "garbanzo beans"); citation order is "the Notational Plane". Throughout: "Remember the purpose of the classification and the users."
- **Marginal subjects** (§2.5, after Vickery 1960): borrow from another classification for a few stray terms; file by the users' association when needed; and "If too many things are filed under 'Other,' ... re-examine the classification and see if it needs rearrangement or a new facet."
- **On the web** (§4.2): four principles: no query that is known to return nothing; users always see where they are; users can always refine; "The URL is the notation for the classification".
